Likely cause

OPENAI_INGREDIENT_EXPLANATION_MODEL is not set

Translation happens at runtime through the LLM. When the model env var is missing, the translator's LLM call short-circuits to null, and the caller falls back to the English source text. Your most recent boot log confirmed this warning:

Seen in your logs 
WARN [OpenAiExplanationProvider] OPENAI_INGREDIENT_EXPLANATION_MODEL is not set.
Ingredient explanations will be skipped; clients will receive deterministic findings only.
Fix 
# .env
OPENAI_API_KEY=sk-...
OPENAI_INGREDIENT_EXPLANATION_MODEL=gpt-5-mini

Then restart and refresh the product detail. The first Swedish request hits the LLM (~1–2 s), subsequent ones return from the cache instantly.

Every place English can be returned — ranked by likelihood for your case

Most likely Model env missing

Your boot log flagged this one. Without the model, callLlm() returns null on step 7 and the caller falls back to English.

$ env | grep OPENAI
OPENAI_API_KEY=sk-…
OPENAI_INGREDIENT_EXPLANATION_MODEL=  // unset

Fix: set it in .env, restart.

Also check API key missing

Same shape. If the key is blank in the running environment, step 7 returns null before even checking the model.

$ env | grep OPENAI_API_KEY
Possible Source language mis-configured

If INGREDIENT_TRANSLATION_SOURCE_LANGUAGE is set to sv, the service thinks the DB content is Swedish and every sv request short-circuits at step 5.

$ env | grep INGREDIENT_TRANSLATION_SOURCE_LANGUAGE

Should be unset or en.

Possible Locale never left the UI

If useLocale() returns 'en' (e.g., the user's locale cookie is stale), the body carries language: 'en' and step 5 is a correct pass-through.

document.cookie   // look for NEXT_LOCALE=sv

What to look for in the backend logs

Log line Means Do
{"event":"translation_skipped","reason":"missing_model_env"} Model env not set. Swedish request returned as English. Set OPENAI_INGREDIENT_EXPLANATION_MODEL.
{"event":"translation_skipped","reason":"missing_api_key"} API key missing. Set OPENAI_API_KEY.
{"event":"translation_failed","reason":"http_error","status":…} OpenAI call failed — bad model name, quota, network. Verify the model id is real; check OpenAI status.
{"event":"translation_failed","reason":"empty_output"} OpenAI returned 200 but no text. Usually a prompt/model interaction issue. Retry with a different model.
No log, just English Step 5 short-circuit: target language equals source language. Check INGREDIENT_TRANSLATION_SOURCE_LANGUAGE and the body's language field.

Quick recovery checklist

Get Swedish back in 60 seconds

  1. Set OPENAI_API_KEY and OPENAI_INGREDIENT_EXPLANATION_MODEL in .env.
  2. Restart the backend. Confirm the "OPENAI_INGREDIENT_EXPLANATION_MODEL is not set" warning is gone.
  3. Open a product detail in the app with the locale set to Swedish. First load takes a second or two (LLM warming the cache).
  4. Refresh — now it's instant (cache hit from ingredient_translation_cache).
  5. Double-check: SELECT * FROM ingredient_translation_cache LIMIT 5; — rows with language = 'sv' should appear.
Env vars
OPENAI_API_KEY, OPENAI_INGREDIENT_EXPLANATION_MODEL, optional INGREDIENT_TRANSLATION_SOURCE_LANGUAGE (default en).
Cache table
ingredient_translation_cache(source_hash, language, translated_text) — truncate to force retranslation.
Cache key
sha256(sourceText) + language. Edit the English text → new hash → next request hits the LLM.
